# Inkward Bound — 界面交接文档(给 AI 生成工具的上下文)

这份文档用于把浏览器界面的现状交给外部 AI 工具协作**重做视觉层**。
把整份文档粘贴给对方,再附上要改的文件,它就有足够上下文而不会破坏系统。

> 文档里一律用**函数名和常量名**定位,不用行号。行号会随着每次改动失效,
> 而这份文档正是因为行号全部错位过一次才重写的。

---

## 0. 一句话说明这个项目

一个交互装置:观众在浏览器画布上按住并移动手指,浏览器把这个手势换算成一个 0→1 的
**收敛值 `c`**,通过 WebSocket 发给 TouchDesigner,由 TD 实时 scrub 播放一段墨水扩散视频。

`c = 0` 是墨水离散的状态,`c = 1` 是墨水凝结的状态。手势越久、越稳、越不躁动,`c` 越接近 1。

**浏览器画布本身也是作品的一部分**——它用一层密度场同步演示"离散 → 凝结"这个过程。
需要重做的就是这一层。

## 2. 绝对不能改的部分(改了会拆掉整个系统)

### 2.1 发给 TouchDesigner 的 JSON 数据契约

`sendTouchData()` 以 30fps 发送。TouchDesigner 那边按字段名解析,**字段名和取值范围都不能变**:

```json
{
  "event":      "down" | "move" | "up" | "frame",
  "isTouching": true,
  "x":          0.5,      // 0..1，归一化坐标
  "y":          0.5,      // 0..1
  "duration":   2.4,      // 秒
  "speed":      0.12,     // 0..1，按 SPEED_MAX 归一化
  "stability":  0.88,     // 0..1
  "agitation":  0.16,     // 0..1
  "clickCount": 1,        // 见下方说明
  "c":          0.42,     // 0..1  ← 最关键的字段
  "state":      "search",
  "timestamp":  1782864000000
}
```

`state` 的五个合法取值:`autonomous` / `disturbance` / `search` / `return_` / `rediffusion`
(注意 `return_` 带下划线,因为 `return` 是保留字)。

**关于 `clickCount`:** 它仍然被计算、仍然发送,但**界面内部已经没有任何逻辑使用它**。
它曾经给 `agitation` 托一个 0.35 的下限,导致以连点开头的手势后面无论多安静都无法沉降,
因此被摘除。字段保留是为了契约不变——不要因为"看起来没用"就删掉它。

### 2.2 c 值引擎(`updateState()`)

```js
cTarget = min(duration/18, 1)*0.7 + stability*0.3 - agitation*0.2   // 钳制 0..1
cValue += (cTarget - cValue) * C_SMOOTH   // 0.06，按住时平滑逼近
cValue -= C_DECAY                          // 0.012，松手时线性衰减
```

权重 `0.7 + 0.3 = 1.0` 是刻意的:只有这样,一次足够长且稳定的按压才能让 `c` 真正到达 1.0,
而 TouchDesigner 那边视频帧号是 `index = c * 480`——`c` 到不了 1,视频就永远播不到最后一帧。
**不要改这些系数。**

同一个函数里还有一处容易被误删的逻辑:

```js
if (isTouching && millis() - lastMoveTime > 60) rawSpeed *= 0.90;
```

手指停住不动时不会再触发 move 事件,`rawSpeed` 会冻结在最后一次测到的值上,系统永远不知道
手势已经停了。这行衰减正是"停下来等待"能被读成静止的原因。删掉它,按住不动就再也涨不到高 `c`。

### 2.3 WebSocket 连接逻辑(`connectWS()`)

自动按页面协议切换 `ws:` / `wss:`,断线后每 2 秒重连。现场演出靠这个容错。

### 2.4 `app.js` 整个文件

它只是个广播中继,不含业务逻辑。重做视觉完全不需要碰它。

## 3. 可以自由重做的部分

当前的视觉是一层**密度场(雾场)**,不是可数的点。它由三层叠加而成,理解这三层的关系
比理解任何单个参数都重要。

### 3.0 渲染架构:三层 + blend 顺序

`draw()` 每帧按固定顺序走,**顺序本身是有原因的**:

```
1. blendMode(BLEND)   画一个半透明黑色矩形擦除上一帧 → 形成拖影
2. paintGlowTex(c)    按 c 重新着色那张辉光贴图
3. blendMode(ADD)     切到加法混合，开始累积光
4. drawResidue(c)     触摸残留层
5. 粒子层 update + draw
6. 触摸点柔光核
7. blendMode(BLEND)   切回普通混合，画有边缘的东西
8. 触摸圆环（唯一的描边）+ 闲置提示文字
```

**为什么圆环单独放在最后、且不在 ADD 之下:** 整幅画面由累积的光构成,没有任何轮廓;圆环是其中唯一一条被"画"出来的线。雾说明聚拢了多少,圆环说明手在哪里——两句不同的话,所以用两种不同的记号。圆环半径随 c 收缩,手越稳,圈越收拢,和墨的动作同向。

**为什么擦除必须在 BLEND 下做:** 加法混合里画黑色等于什么都没画。如果把擦除放进 ADD,
拖影就永远不会消退,画面会一路累积到全白。

**为什么用一张预渲染贴图(`glowTex`):** 每个粒子每帧都实时画一个径向渐变,是每秒几千次
渐变运算。现在改成:整帧只重绘**一次**贴图(`paintGlowTex`),然后所有粒子和残留都
`image()` 这同一张贴图,靠 `globalAlpha` 和尺寸变化区分。

**密度是怎么来的:** 单个粒子的亮度被刻意压得远低于白色(`GLOW_A_LOW/HIGH` 只有 16–30)。
在 ADD 之下,只有粒子真正**聚集**的地方,叠加才会累积到接近白;稀疏处保持暗灰。
**图像是由重叠量构成的,不是由画出来的形状构成的**——这就是"密度"的视觉来源。
重做视觉时如果换掉这个机制,请确保新的机制同样能表达"聚集程度"。

### 3.1 调参区(`FOG LOOK` 常量块)

所有视觉参数集中在 `sketch.js` 顶部一个块里,**改这些不会碰到物理和数据管线**:

| 常量 | 当前值 | 作用 |
|---|---|---|
| `GLOW_TEX` | 128 | 辉光贴图分辨率 |
| `GLOW_R_LOW` / `HIGH` | 17 / 38 | c=0 → c=1 的辉光半径(细碎雾 → 融合云) |
| `GLOW_A_LOW` / `HIGH` | 16 / 30 | c=0 → c=1 的单粒子透明度 |
| `FOG_LOW` / `FOG_HIGH` | [176,176,176] / [242,242,242] | c=0 → c=1 的色值,单色 |
| `TRAIL_LIFE` | 1.2 | 触摸残留寿命(秒) |
| `TRAIL_GAIN` | 1.18 | 残留比基础雾亮约 18% |
| `TRAIL_MAX` | 220 | 残留池上限 |
| `TRAIL_MIN_D` | 6 | 移动多少像素才落下一个新残留 |
| `N_PART` | 130 | 粒子数。比旧的点阵版少,因为每个粒子现在是一团宽辉光 |
| `RING_R_LOW` / `HIGH` | 62 / 24 | 触摸圆环半径,c=0 → c=1(张开搜寻 → 收拢) |
| `RING_A_LOW` / `HIGH` | 70 / 130 | 圆环描边不透明度 |
| `RING_OUTER` | 1.9 | 外圈相对内圈的倍数 |
| `TIP_SIZE` | 16 | "HOLD TO SEARCH" 字号 |

### 3.2 粒子物理(`Particle.update()`)

物理层与旧的点阵版**完全一致**,只有渲染改了。核心原则是
**每一个参数都被 `c` 连续调制**,让画面自己演示离散→凝结。重做时可以换任何视觉形式,
但请保留这个原则:

| 参数 | c = 0(离散) | c = 1(凝结) |
|---|---|---|
| 噪声尺度 `noiseScale` | 0.0060(细碎) | 0.0022(大结构) |
| 移动速度 `spd` | 2.8 | 0.4(变慢) |
| 噪声演进速度 | 0.012 | 0.003 |
| 向心引力 `pull` | 0 | 0.035(收拢) |
| 触摸作用方向 `dir` | 1(排斥) | -0.3(轻微吸引) |
| 拖影擦除强度 | 18(短拖尾) | 6(长拖尾) |

另外:`agitation > 0.4` 时给速度叠加高斯抖动,并让辉光尺寸随机散开——
这是"人为扰动"状态的视觉表达,云的边缘会碎掉、翻搅而不是维持光滑边界。

### 3.3 触摸残留层(`spawnResidue()` / `drawResidue()`)

一个**独立于 `c`** 的图层:手指刚走过的路径会按自己的时钟发光约 1.2 秒。
它不受 `c` 调制——但因为高 `c` 会减慢全局拖影擦除,残留在高 `c` 时**看起来**更持久。
这个对比是涌现出来的,不是写死的。重做时如果要保留这一层,请保留这个"两套时钟"的关系。

### 3.4 两套 HUD

- `#hud` —— 底部状态条,给创作者调试用:C / STAB / AGIT / DUR + 连接指示灯 `#ws-dot`
- `#sys-hud` —— 浮层系统面板,给观众看的:按住时淡入,松手后在衰减期间保持可见

**如果重做 HUD,必须保留这些 element id**,因为 `updateState()` 每帧用
`document.getElementById()` 直接写入:

```
v-c  v-s  v-a  v-d  state-txt          （底部条）
sys-c  sys-s  sys-a  sys-d  sys-state  （浮层面板）
ws-dot                                  （连接指示灯，className: try/on/off）
sys-hud                                 （靠 .visible class 控制淡入淡出）
```

如果想改成别的结构,请同步修改 `updateState()` 末尾那段 DOM 写入代码。

### 3.5 状态配色(`STATE_COLORS`)

五个状态各有一个色值,目前只用于给 `#state-txt` 上色。可以扩展成整体主题色。

```js
autonomous:  '#1a1a22'   disturbance: '#221010'   search: '#101622'
return_:     '#141e1e'   rediffusion: '#0e0e14'
```

## 4. 坐标系约定(一个踩过的坑)

`createCanvas(windowWidth, windowHeight - HUD_H)` **已经**扣掉了底部 HUD 的高度,
所以画布高度 `height` 就是粒子应该活动的完整区域。

`Particle.update()` 里曾经写成 `zone = height - HUD_H`,**又扣了一次**,造成粒子场比画布短
36px,并且触摸光圈的位置和粒子实际受力中心最多差 36px。现在已修正为 `zone = height`。

**新增任何用到纵向坐标的代码时,直接用 `height`,不要再减 `HUD_H`。**

## 5. 交互行为参考

- **鼠标和触摸都支持**,两套事件走同样的 `startTouch` / `moveTouch` / `endTouch`
- **按 `F` 进出全屏**(`keyPressed()`)
- **闲置提示**:未触摸且 `c < 0.1` 时,画面中央闪烁显示 "HOLD TO SEARCH"
- 所有事件处理函数都 `return false`,用于阻止移动端的默认滚动/缩放行为
- **速度测量**:`moveTouch()` 用当前点与 `touchX/touchY`(此刻仍是上一个位置)之差除以 `dt`。
  不要引入额外的 `prevX/prevY` 变量——之前那版正是因为赋值顺序错了,把速度算成了两倍。

## 6. 本地运行

```bash
cd InkWard_Bound_Interface
npm ci
npm start
# 浏览器打开 http://localhost:3000
# 用平板测触摸：同一网络下打开 http://<这台机器的局域网 IP>:3000
```

不需要 TouchDesigner 也能开发视觉——WebSocket 连不上时 `sendTouchData()` 会直接返回,
`c` 值引擎和粒子系统照常运行,底部指示灯显示为断开(红色)。
