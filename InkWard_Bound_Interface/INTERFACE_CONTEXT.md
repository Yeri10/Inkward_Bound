# Inkward Bound — 界面交接文档(给 AI 生成工具的上下文)

这份文档用于把浏览器界面的现状交给外部 AI 工具协作**重做视觉层**。
把整份文档粘贴给对方,再附上要改的文件,它就有足够上下文而不会破坏系统。

> 文档里一律用**函数名和常量名**定位,不用行号。行号会随着每次改动失效,
> 而这份文档正是因为行号全部错位过一次才重写的。

---

## 0. 一句话说明这个项目

一个交互装置:观众在浏览器画布上按住并移动手指,浏览器把这个手势换算成一个 0→1 的
**收敛值 `c`**,通过 WebSocket 发给 TouchDesigner,由 TD 实时 scrub 播放一段墨水扩散视频。

`c = 0` 是墨水离散的状态,`c = 1` 是墨水凝结的状态。手势越久、越稳、越不躁动,`c` 越接近 1。

**浏览器画布本身也是作品的一部分**——它用一层密度场同步演示"离散 → 凝结"这个过程。
需要重做的就是这一层。

## 2. 绝对不能改的部分(改了会拆掉整个系统)

### 2.1 发给 TouchDesigner 的 JSON 数据契约

`sendTouchData()` 以 30fps 发送。TouchDesigner 那边按字段名解析,**字段名和取值范围都不能变**:

```json
{
  "event":      "down" | "move" | "up" | "frame",
  "isTouching": true,
  "x":          0.5,      // 0..1，归一化坐标
  "y":          0.5,      // 0..1
  "duration":   2.4,      // 秒
  "speed":      0.12,     // 0..1，按 SPEED_MAX 归一化
  "stability":  0.88,     // 0..1
  "agitation":  0.16,     // 0..1
  "clickCount": 1,        // 见下方说明
  "c":          0.42,     // 0..1  ← 最关键的字段
  "state":      "search",
  "timestamp":  1782864000000
}
```

`state` 的五个合法取值:`autonomous` / `disturbance` / `search` / `return_` / `rediffusion`
(注意 `return_` 带下划线,因为 `return` 是保留字)。

**关于 `clickCount`:** 它仍然被计算、仍然发送,但**界面内部已经没有任何逻辑使用它**。
它曾经给 `agitation` 托一个 0.35 的下限,导致以连点开头的手势后面无论多安静都无法沉降,
因此被摘除。字段保留是为了契约不变——不要因为"看起来没用"就删掉它。

### 2.2 c 值引擎(`updateState()`)

```js
cTarget = min(duration/18, 1)*0.7 + stability*0.3 - agitation*0.2   // 钳制 0..1
cValue += (cTarget - cValue) * C_SMOOTH   // 0.06，按住时平滑逼近
cValue -= C_DECAY                          // 0.012，松手时线性衰减
```

权重 `0.7 + 0.3 = 1.0` 是刻意的:只有这样,一次足够长且稳定的按压才能让 `c` 真正到达 1.0,
而 TouchDesigner 那边视频帧号是 `index = c * 480`——`c` 到不了 1,视频就永远播不到最后一帧。
**不要改这些系数。**

同一个函数里还有一处容易被误删的逻辑:

```js
if (isTouching && millis() - lastMoveTime > 60) rawSpeed *= 0.90;
```

手指停住不动时不会再触发 move 事件,`rawSpeed` 会冻结在最后一次测到的值上,系统永远不知道
手势已经停了。这行衰减正是"停下来等待"能被读成静止的原因。删掉它,按住不动就再也涨不到高 `c`。

### 2.3 WebSocket 连接逻辑(`connectWS()`)

自动按页面协议切换 `ws:` / `wss:`,断线后每 2 秒重连。现场演出靠这个容错。

### 2.4 `app.js` 整个文件

它只是个广播中继,不含业务逻辑。重做视觉完全不需要碰它。

## 3. 可以自由重做的部分

当前的视觉是一层**密度场**:一组柔光节点,大小、不透明度、形状各不相同。离散还是聚拢,主要由
"每个节点有多亮、有多宽"表达;节点也会漂移和汇聚,但速度远低于自身半径(见 §3.0)。

### 3.0 唯一的硬性约束:每帧位移 ÷ 辉光半径 < 0.05

早先的版本是粒子在 Perlin 流场里游动,整片看起来像蝌蚪在游。**问题不是审美的,是可以算出来的:
当一个核每帧走的距离和它自己的辉光半径同量级时,上一帧还没擦干净、这一帧已经挪开,那截正在
消退的残影就会被读成尾巴**——一个亮头拖一条尾。旧参数下这个比值是 0.165。

场后来一度完全静止(比值 0),现在按状态重新引入了运动,但每一处都先算过这个比值:

| 阶段 | 每帧位移 | 辉光半径 | 比值 |
|---|---|---|---|
| 凝结(18 秒向汇聚点靠拢) | 0.26 px | 150 px | **0.0017** |
| LATENT SEARCH 漂移 | 0.06 px | 150 px | **0.0004** |
| 消散(1.4 秒) | 5.6 px | 150→390 px | **0.037** |
| ~~旧的流场粒子~~ | 2.8 px | 17 px | ~~0.165~~ |

**加任何新动效之前先算这个数。** 消散那一条尤其值得看:spec 要求"1.5 秒内趋近于零",
但如果让位置也在 1.4 秒内飞回原处,比值会冲到 0.149,尾巴立刻回来。解法是
**把快的部分交给 sigma 和 alpha,位置仍用同一个缓速回归**——alpha 早已趋零,没人看得见它
慢慢回去。

### 3.1 渲染顺序

```
1. blendMode(BLEND) + background(0)   整帧清空
2. paintGlowTex(c)                    c 跨过量化档时才重新着色
3. spawnResidue()                     必要时落下一个残留核
4. blendMode(ADD)                     加法混合，开始累积光
5. drawField(c)                       密度场
6. drawTrail()                        残留层 + 主轨迹头部
7. drawMark(...)                      触摸亮斑，或待机信标
8. blendMode(BLEND)                   切回普通混合
9. drawRings(...)                     触摸/待机的外圈，唯一的描边
10. HOLD TO SEARCH                    唯一的文字
```

**为什么整帧清空而不是半透明擦除:** 半透明擦除的作用是在**快速**运动的物体后面留一层正在
消退的上一帧。这里没有任何东西接近那个速度,那层残影就只是等着变成拖影。轨迹的持久感由
`drawTrail()` 自己的时钟给,不靠画布残留。

**为什么用预渲染贴图(`glowTexes`):** 每个节点每帧都实时画一个径向渐变,是每秒几万次
渐变运算。现在贴图只有 **6 张**,而且只在 `c` 跨过量化档时才重绘,节点各自 `image()` 分到的
那张,靠 `globalAlpha`、尺寸和旋转区分。

**密度是怎么来的:** 单个节点的亮度被刻意压得极低(`NODE_A_LOW/HIGH` 只有 10–20)。
在 ADD 之下,只有节点真正**聚集**的地方,叠加才会累积到接近白;稀疏处保持暗灰。
**图像是由重叠量构成的,不是由画出来的形状构成的。**

### 3.2 场的构成(`buildField()`)

`N_CLUSTER` 个团心随机撒在画面里(0.06–0.94,比原来的 0.12–0.88 宽,否则场永远离画框
同样远)。多数节点用**高斯偏移**落在团心周围——不是均匀分布,中心密、向外稀,这才让每一团
读作柔和的热区而不是一个圆盘。

**另外两处防止规律性:**

- **归属随机而非轮转。** 原来用 `i % N_CLUSTER`,每团节点数完全相等(17/17/17/17/17),
  这种整齐是看得出来的。现在随机分配,一次建场可能是 19/22/29/15。
- **`STRAY_FRAC` 比例的游离节点**落在画面任意位置,不属于任何团心,`rank` 取 0.7–1
  (按团缘处理,所以聚拢时会先熄灭)。没有它们,场会解析成可数的几个规整光斑。

**闪烁区块的大小由 `N_CLUSTER` 和 `CLUSTER_SD` 共同决定**——因为闪烁是按团相关的
(见下文),团有多大,一起明灭的区块就有多大。

每个节点有八个固定属性:`size`(半径倍数)、**`amul`(亮度倍数)**、`rank`(0 = 团心,1 = 团缘)、
`ph`(呼吸相位)、`tex`(用哪张贴图变体)、`asp`(基础长宽比)、`rot`(基础朝向)、
`seed`(它在 noise 场里的通道)。

**`size` 和 `amul` 是两个独立的轴**,这一点很重要:之前所有节点共用同一个基准亮度,固定差异
只剩宽度,看起来像同一种物质切成不同大小。现在"宽而淡"和"小而浓"都存在,节点之间的
固定亮度跨度从 1.3 倍拉到 **19 倍**——最暗的几乎只在重叠处才可见,最亮的单张也只有 39/255,
仍远低于白,所以出白依然只能靠叠加。
位置存的是归一化坐标,所以改窗口大小是重新排布同一片场,不是换一片新的。

### 3.3 c 如何让场"聚拢"

靠的是 `rank` 的权重曲线:

| rank | c = 0 | c = 0.5 | c = 1 |
|---|---|---|---|
| 0.0(团心) | 1.00 | 1.45 | **1.90** |
| 0.6 | 0.85 | 0.58 | 0.30 |
| 1.0(团缘) | 0.75 | 0.38 | **0.00** |

c = 0 时权重几乎是平的,整片是均匀的薄雾;c = 1 时急剧向团心倾斜,团缘熄灭。
**场在它本来就在的地方变浓。** 这是聚拢的主要来源;位置向汇聚点的靠拢(§3.3b-2)是次要的
第二重,两者叠加才读作"多个模糊点正在合并成一个更确定的形状"。

同时 `NODE_R_LOW → NODE_R_HIGH`(150 → 250)让节点变宽,团心因此互相融合。

**闪烁必须分两级,这是这一层最容易做错的地方。**

第一版只给每个节点一条独立的闪烁通道,结果**完全看不见**。原因是统计性的:
**N 层各自波动 ±A 的东西叠加起来,合计只波动 ±A/√N**。c=1 时重叠约 20 层,
节点级 ±15% 到了画面上只剩 ±3%。

相关的波动不会被 √N 稀释。所以现在是两级:

| | 深度 | 20 层重叠后仍可见 |
|---|---|---|
| `CLUS_TWINKLE` 团级(同团共用一条通道) | ±65% | **±65%** |
| `NODE_TWINKLE` 节点级(各自独立) | ±40% | ±8.9% |
| `BREATH_AMT` 整体缓慢起伏(26 秒一轮) | ±10% | ±10% |

**看得见的是团级那一层**——整个热区一起明灭;节点级只是让团不至于读成一块整体在开关。
四个团的速率互相错开,不会同步。

**还有一个坑:`NOISE_STRETCH`。** p5 的 `noise()` 叠了四个倍频,数值几乎不会碰到 0 或 1,
实际大多落在 0.3–0.7。直接写 `(noise-0.5)*2` 只能拿到标称幅度的四成——常量写着 ±38%,
画面上是 ±15%。所有闪烁都乘以 `NOISE_STRETCH` 再钳制,常量才名副其实。

**平均重叠层数**:c=0 约 7 层,c=1 约 20 层。这个数字要保持在 3 以上,低于它就会看出
一个个分开的团而不是连续的雾。改 `N_NODE` 或 `NODE_R_*` 时顺手核一下。

### 3.3b 形状:多曲线 + 各向异性

两件事让这片场不再像"同一个图章盖了 85 次":

**六张贴图,每张自己就是多个高斯的叠加。** 单个径向渐变是**单调**的——离中心越远只会越暗——
所以无论叠多少层,每一个光斑本身都是均匀的。现在每张贴图由 4–8 个**位置偏移、大小和权重
各不相同**的子核加法合成(`buildTexSpecs()`),一个光斑内部因此有局部的隆起和凹陷,
而且这些起伏会跟着缩放、拉伸、旋转一起走。

两个实现上的要点:

- **烘焙进贴图,不在运行时画。** 每个节点实时画 6 个子核 = 每帧 510 次 `image()`,
  在 c=1 那种二十层重叠之下是 3.7 G 像素/秒。烘焙之后运行时开销和原来完全一样。
- **峰值归一(`TEX_PEAK`)。** 子核互相偏移,不会在任何一点同时贡献,所以只按权重和归一化
  的话每张贴图峰值只有 0.53–0.75——比它替换掉的单渐变暗三分之一,而且各张还不一致。
  改为按**实测最大值**重新缩放,六张一样亮,内部起伏不受影响(所有权重同比例缩放)。

贴图用固定种子(`TEX_SEED`)生成,每次刷新都是同一组形状。`c` 变化时才重新着色,且量化到
32 档——按住到底的 18 秒里只重绘 31 次,而不是 1080 次。

**椭圆 + 缓慢漂移。** 每个节点有固定的基础长宽比(`ASP_MIN`–`ASP_MAX`)和朝向,两者各自
在一条低频 noise 通道上漂移(约 10 秒一轮,朝向 ±26°)。宽高按面积守恒推导
(`w*h = d*d`),否则节点被拉长的同时会变亮,漂移就读成了脉动而不是形变。

> **拉伸和旋转不是位移**,所以这一项对拖尾比值的贡献是 0。会让中心移动的只有 §3.3b-2 里的
> 那几项,它们各自的比值都列在 §3.0。

### 3.3b-2 状态驱动的形态

`stateName` 改变的不只是 HUD 上的字,还有场的运动学:

| 状态 | 场的行为 |
|---|---|
| `search` | 节点在各自位置附近缓慢随机游走(`DRIFT_AMT` / `DRIFT_SPD`,约 19 秒一轮) |
| c 上升 | 目标位置按 `c²×CONVERGE` 向汇聚点靠拢,同时 `rank` 权重把光集中到团心 |
| `rediffusion` | 半径按 `DISPERSE_GROW` 快速增大、alpha 按 `DISPERSE_FADE` 淡出;位置仍缓速回归 |

`CONVERGE` 是 0.62 而不是 1.0:所有东西汇到一个点会变成一个圆点,而不是"聚拢"。
`c²` 而非 `c`:按压早期的不确定阶段不该有任何东西移动,聚拢要等手势真正投入之后才可读。

**触摸与扰动**

- **触摸不推开任何东西**,而是抬高手所覆盖区域的密度:`HEAT_R` 内的节点 `heat` 上升,
  离开后按 `HEAT_FALL` 冷却,表现为变亮 + 略微变宽(`HEAT_A` / `HEAT_GROW`)
- **`agitation > 0.4` 时场"沸腾"而不是散开**:节点保持位置,亮度起伏。用 `noise()` 驱动
  而不是 `random()`——整帧清空的画布上每帧取新随机数会变成频闪

### 3.3b-3 双层轨迹(`drawTrail()`)

主轨迹头部和历史残留在**尺寸和亮度上双重分离**,不只是透明度不同:

| | 半径 | alpha |
|---|---|---|
| 头部 | 34 px(固定) | 105 |
| 残留(落下时) | 44 px | 62 |
| 残留(寿命末) | **200 px** | **2**(指数衰减) |

残留核一生变宽 4.5 倍、alpha 只剩 3%——**正在消失的东西看起来是真的在扩散变薄,
而不只是被调暗**。这是 sigma 增长速率和 alpha 衰减必须分开给的原因。

### 3.3b-4 触摸标记:亮斑 + 外圈(`drawMark()` / `drawRings()`)

触摸反馈是**两个记号在做两件事**,同心但半径分开:

- **内层亮斑**(`drawMark`,画在 ADD 段):`MARK_LOBES` 个互相偏移的毛边贴图叠加。
  贴图边缘本来就不规则,再加偏移,轮廓不对称——它是**材料**,说的是聚了多少
- **外层双圈**(`drawRings`,画在 BLEND 段):整幅画面里唯一被"画"出来的线。
  它是**系统**的记号,说的是手在哪里

之所以不合成一个:圆环保持几何正圆,正是它区别于墨的地方;但它不该同时兼任触摸反馈本身,
所以反馈交给毛边亮斑,圆环退到外面(`RING_MUL` = 1.12 倍)。
描边必须在 BLEND 下画——放进 ADD 会溶进它本该衬托的场里。

| | c = 0 | c = 1 |
|---|---|---|
| 亮斑半径 | 52 px | 21 px |
| 内圈 | 58 px | 24 px |
| 外圈 | 93 px | 38 px |

整组标记经过多轮缩小(外圈 c=0 从 239 一路到 93 px)。**继续缩要动 `MARK_R_LOW/HIGH`,
不要再压 `RING_MUL`**——它已经贴着亮斑(只大 12%),再低就切进辉光里,两个记号会糊成一个。

**文字与圈的关系随尺寸变化,调任何一边都要一起看。** `HOLD TO SEARCH` 在 `TIP_SIZE` = 11
时宽约 120px,而待机外圈直径在 100–186px 之间——呼吸到六成以上时文字被外圈容下,呼吸最低点
仍会略微穿出。文字宽度固定,圈在呼吸,所以两者不可能全程包含。
若要文字始终在圈内,把它移到标记下方
(`text()` 的 y 改成 `height/2 + IDLE_R_HIGH * RING_MUL * RING_OUTER + 24`)。

**闪烁(`TWINKLE_AMT` / `TWINKLE_SPD`)。** 亮斑的三片各自在一条独立的 noise 通道上、
以略微错开的速率起伏(每秒约 2.1 / 2.6 / 3.1 次),所以它像穿过空气看到的一个光点那样
不均匀地闪,而不是整体一起呼吸——共用同一时钟就成了脉动,那正是闪烁的反面。

**强度由 `stability` 驱动**:手一动,亮斑变平变稳;手停住,它才活过来(满稳定时单片亮度在
×0.25 到 ×1.75 之间跳)。这件作品整体在说"等待会被回报",这是能把那句话说出来的最小的地方。
待机时没有任何东西在动,所以常驻闪烁。

待机信标用同一对函数,只是在画面中心按呼吸包络明灭。

### 3.4 两套 HUD

- `#hud` —— 底部状态条,给创作者调试用:C / STAB / AGIT / DUR + 连接指示灯 `#ws-dot`
- `#sys-hud` —— 浮层系统面板,给观众看的:按住时淡入,松手后在衰减期间保持可见

**如果重做 HUD,必须保留这些 element id**,因为 `updateState()` 每帧用
`document.getElementById()` 直接写入:

```
v-c  v-s  v-a  v-d  state-txt          （底部条）
sys-c  sys-s  sys-a  sys-d  sys-state  （浮层面板）
ws-dot                                  （连接指示灯，className: try/on/off）
sys-hud                                 （靠 .visible class 控制淡入淡出）
```

如果想改成别的结构,请同步修改 `updateState()` 末尾那段 DOM 写入代码。

## 4. 坐标系约定(一个踩过的坑)

`createCanvas(windowWidth, windowHeight - HUD_H)` **已经**扣掉了底部 HUD 的高度,
所以画布高度 `height` 就是密度场应该铺满的完整区域。

旧的粒子实现里曾经写成 `zone = height - HUD_H`,**又扣了一次**,造成场比画布短 36px,
并且触摸光圈的位置和粒子实际受力中心最多差 36px。现在整个渲染层用归一化坐标乘 `width`
/ `height`,不再出现这个减法。

**新增任何用到纵向坐标的代码时,直接用 `height`,不要再减 `HUD_H`。**

## 5. 交互行为参考

- **鼠标和触摸都支持**,两套事件走同样的 `startTouch` / `moveTouch` / `endTouch`
- **按 `F` 进出全屏**(`keyPressed()`)
- **闲置提示**:未触摸且 `c < 0.1` 时,画面中央出现一组呼吸的圆环,"HOLD TO SEARCH" 就落在
  圆心上。圆环和文字共用同一条余弦包络,一起明灭——圆环预示触摸会长成什么样子,文字说明
  要做什么,两者应当同时抵达。原先是 `frameCount % 120 < 60` 的硬开关,在切换帧上是 0 到 1
  的跳变,看起来是闪的。注意文字宽约 175px,而内圈直径只有 68–124px,内圈会从字中间穿过
- 所有事件处理函数都 `return false`,用于阻止移动端的默认滚动/缩放行为
- **速度测量**:`moveTouch()` 用当前点与 `touchX/touchY`(此刻仍是上一个位置)之差除以 `dt`。
  不要引入额外的 `prevX/prevY` 变量——之前那版正是因为赋值顺序错了,把速度算成了两倍。
